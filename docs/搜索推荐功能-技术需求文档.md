# 搜索推荐功能技术需求文档

生成日期：2026-07-28

## 1. 目标

本技术需求文档只覆盖第一阶段的“搜索推荐功能”实现。

目标是打通这样一条最小链路：

1. 用户在搜索栏输入关键词
2. 应用根据关键词请求 Wikipedia 搜索接口
3. 应用将接口返回结果转换为内部模型
4. ViewModel 产出统一的 UI 状态
5. UI 渲染推荐列表

本阶段不包含：

- 点击推荐项进入详情页
- 收藏
- 历史
- 本地缓存
- 多语言搜索

---

## 2. 现有项目分层复用原则

当前项目已经存在明确分层，新的搜索推荐能力应沿用同样结构：

- `core:network`
  负责远端接口和网络 DTO
- `core:model`
  负责应用内部稳定模型
- `core:data`
  负责 repository 和数据转换
- `core:domain`
  负责 use case
- `feature:search:impl`
  负责 ViewModel、UI state 和页面渲染

不建议让 UI 直接消费 Wikipedia 原始 JSON。

---

## 3. 技术实现链路

推荐采用以下实现链路：

1. `SearchScreen`
   用户输入关键词
2. `SearchViewModel`
   维护 query 和 UI state
3. `SearchWikiSuggestionsUseCase`
   调用 repository
4. `WikiSearchRepository`
   组织搜索行为
5. `WikipediaNetworkDataSource`
   请求 Wikipedia 接口
6. `NetworkWikiSearchResponse / NetworkWikiSearchItem`
   承接原始返回
7. `WikiSearchResult / WikiSearchItem`
   转成应用内部模型
8. `SearchSuggestionUiState`
   给 UI 渲染使用

---

## 4. 依赖接口

第一阶段推荐使用：

- `GET /w/rest.php/v1/search/page?q={query}`

原因：

- 返回结果中包含标题、描述、摘要片段、缩略图
- 比只返回标题的接口更适合直接做推荐列表

---

## 5. 需要新增或调整的模块

### 5.1 `core:model`

需要新增应用内部稳定模型。

#### `WikiSearchItem`

表示单个推荐结果项。

建议字段：

- `id: Long`
- `key: String`
- `title: String`
- `description: String?`
- `excerpt: String?`
- `thumbnailUrl: String?`

职责：

- 作为 UI 最终消费的数据结构
- 屏蔽网络层原始字段差异

#### `WikiSearchResult`

表示一次搜索的完整结果集合。

建议字段：

- `items: List<WikiSearchItem>`

职责：

- 作为 domain / repository 的返回包装

---

### 5.2 `core:network`

需要新增 Wikipedia 搜索接口和网络 DTO。

#### `NetworkWikiSearchResponse`

表示搜索接口顶层返回。

建议字段：

- `pages: List<NetworkWikiSearchItem>`

#### `NetworkWikiSearchItem`

表示接口中的单个原始结果项。

建议字段：

- `id: Long`
- `key: String`
- `title: String`
- `excerpt: String?`
- `matchedTitle: String?`
- `anchor: String?`
- `description: String?`
- `thumbnail: NetworkWikiThumbnail?`

#### `NetworkWikiThumbnail`

表示缩略图信息。

建议字段：

- `url: String`
- `width: Int?`
- `height: Int?`
- `mimetype: String?`

#### `WikipediaApi`

负责 Retrofit 接口定义。

建议能力：

- `searchPages(query: String): NetworkWikiSearchResponse`

#### `WikipediaNetworkDataSource`

负责对 `WikipediaApi` 的调用封装。

职责：

- 统一网络请求入口
- 隔离 Retrofit 细节

---

### 5.3 `core:data`

需要新增 repository 和映射逻辑。

#### `WikiSearchRepository`

建议接口：

- `suspend fun searchSuggestions(query: String): WikiSearchResult`

职责：

- 对上提供统一搜索能力

#### `DefaultWikiSearchRepository`

职责：

- 调用 `WikipediaNetworkDataSource`
- 将 `NetworkWikiSearchResponse` 转换为 `WikiSearchResult`
- 清洗空字段

#### 映射函数

建议新增映射：

- `NetworkWikiSearchItem -> WikiSearchItem`
- `NetworkWikiSearchResponse -> WikiSearchResult`

映射规则建议：

- `thumbnailUrl` 只暴露最终可用 URL
- `excerpt` 保留原始摘要片段，后续可再清洗 HTML 标签
- `description` 允许为空

---

### 5.4 `core:domain`

需要新增 use case。

#### `SearchWikiSuggestionsUseCase`

建议接口：

- `operator fun invoke(query: String): Flow<WikiSearchResult>`

或者第一版也可以使用：

- `suspend operator fun invoke(query: String): WikiSearchResult`

职责：

- 接收 query
- 调用 repository
- 对 query 做基础处理，例如 `trim`

第一版不在 use case 层做复杂 debounce 或缓存。

---

### 5.5 `feature:search:impl`

需要改造搜索页面逻辑，使其从原来的“本地 FTS 搜 news/topic”切换为“远端 Wikipedia 推荐结果”。

#### `SearchSuggestionUiState`

建议新增或替换现有状态模型。

至少包含：

- `Idle`
- `Loading`
- `Success(items: List<WikiSearchItem>)`
- `Empty`
- `Error`

#### `SearchViewModel`

职责：

- 维护输入框 query
- 在 query 变化时触发推荐请求
- 接 use case 返回结果
- 输出统一 UI state

第一版交互策略建议：

- 当 query 为空或全空格时，不请求
- 当 query 长度不足最小阈值时，不请求
- 当 query 合法时发起请求

#### `SearchScreen`

职责：

- 渲染输入框
- 观察 `SearchSuggestionUiState`
- 展示推荐列表
- 展示空状态和错误状态

#### `SearchSuggestionItem`

建议新增单独的搜索推荐列表项组件。

展示字段：

- 标题
- 描述
- 摘要片段
- 缩略图

第一版点击行为可先留空或只透传回调，不做跳转。

---

## 6. 数据结构类清单

第一阶段建议新增以下数据结构类：

### 网络层 DTO

- `NetworkWikiSearchResponse`
- `NetworkWikiSearchItem`
- `NetworkWikiThumbnail`

### 应用内部模型

- `WikiSearchResult`
- `WikiSearchItem`

### UI 状态模型

- `SearchSuggestionUiState`

---

## 7. 状态流设计

推荐的状态流转如下：

1. 初始进入页面
   - `Idle`
2. 用户输入合法 query
   - `Loading`
3. 请求成功且有结果
   - `Success`
4. 请求成功但无结果
   - `Empty`
5. 请求失败
   - `Error`

---

## 8. 边界与异常处理

需要明确处理：

- 空 query
- 只有空格的 query
- 网络失败
- 接口返回空列表
- 缺失缩略图
- 缺失描述

建议策略：

- 空 query：直接回到 `Idle`
- 无结果：进入 `Empty`
- 失败：进入 `Error`
- 无图：展示无图样式，不阻塞列表显示

---

## 9. 第一阶段验收标准

满足以下条件即可认为“搜索推荐功能”技术实现完成：

1. 输入合法关键词后，应用能够成功请求 Wikipedia 搜索接口
2. 返回结果能被转换为内部模型
3. ViewModel 能输出稳定的推荐 UI state
4. UI 能展示推荐列表
5. UI 能处理空状态与错误状态
6. UI 不直接依赖 Wikipedia 原始 JSON 字段
