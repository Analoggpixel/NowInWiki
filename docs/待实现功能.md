## 通知按用户偏好截取（未开始）

- 状态：待实现
- 背景：`SystemTrayNotifier` 目前用 `newsResources.take(5)`，只截列表前 5 条，不看用户偏好
- 目标：根据用户关注主题、浏览/已读等，筛选排序后再取最多 5 条再发通知
- 建议落点（业务层，不要塞进 Notifier）：
  - 调用方：`OfflineFirstNewsRepository` 里 `notifier.postNewsNotifications(...)` 之前
  - 或抽 UseCase：如 `SelectNewsForNotificationUseCase`
- `SystemTrayNotifier`：继续只负责展示与数量上限兜底
- 可用信号：
  - 已有：关注主题 `followedTopics`
  - 待补：浏览历史、已读状态等（若要做更细偏好）
- 验收大致标准：
  - 有关注时优先推相关新闻
  - 无偏好数据时行为与现在兼容（列表前 N 条）
  - demo / 测试仍可用 `NoOpNotifier`，不依赖系统通知

### 相关代码

- `core/notifications/.../SystemTrayNotifier.kt`（`take(MAX_NUM_NOTIFICATIONS)`）
- `core/data/.../OfflineFirstNewsRepository.kt`（调用 `postNewsNotifications`）

## 接入 RSSHub 作为 NewsResource 数据源（未开始）

- 状态：待实现
- 背景：当前新闻来自 NiA 自有后端 / demo JSON；希望用 RSSHub 拉取（可含中文 ACG 等路由）作为资讯源
- 目标：`GET {RSSHub实例}/{路由}?format=json`，将 JSON Feed 的 `items` 映射为 `NetworkNewsResource`（及可选 Topic），经现有 data 层进 App
- 建议做法：
  - 新增数据源实现（如 `RssHubNiaNetworkDataSource`），或扩展 `NiaNetworkDataSource` / flavor 绑定
  - 字段映射大致：`id`/`url`→id/url，`title`→title，`content_html`/`summary`→content，`image`→headerImageUrl，`date_published`→publishDate；topics 可按路由或 tags 自建
  - ChangeList 增量：RSSHub 通常无对等接口，可先全量/按时间拉，或本地自行算变更
  - 公共 `rsshub.app` 可能限流不稳，认真用建议自建实例
- 参考：
  - 请求：HTTP GET，路由见 RSSHub 文档（二次元等）
  - 响应：默认 RSS XML；App 侧优先 `?format=json`（JSON Feed）
- 相关代码：
  - `core/network/.../NiaNetworkDataSource.kt`、`RetrofitNiaNetwork.kt`、`DemoNiaNetworkDataSource.kt`
  - `core/network/.../model/NetworkNewsResource.kt`

## 接入 Wikipedia HTTP API 作为补充数据源（未开始）

- 状态：待实现
- 与上条关系：和「接入 RSSHub」同属「新增外部 HTTP 数据源」学习向改造，可对照实现；不必替代 RSSHub
- 背景：Wikipedia / MediaWiki 对外提供 HTTP API；内容为 CC BY-SA 开放许可，软件 MediaWiki 开源
- 目标：用现有 Retrofit / OkHttp 请求官方 API，按需映射为 App 可用模型（词条摘要、搜索结果等；是否并入 `NewsResource` 视场景再定）
- 可用接口（择一或组合）：
  - MediaWiki Action API：如 `https://zh.wikipedia.org/w/api.php?...`
  - MediaWiki REST API：见 Wikimedia 文档
- 注意：
  - 请求须带合理 User-Agent（App 名 + 联系方式），勿用默认空 UA
  - 遵守速率限制，勿高频爬取；优先官方 API，不要爬 HTML
  - 展示内容时按 CC BY-SA 要求署名
- 建议做法：
  - 新增独立 DataSource / Repository（如 `WikipediaNetworkDataSource`），与 RSSHub / NiA 后端并列，便于对比学习
  - 先做「搜索词条 → 展示摘要」最小闭环，再考虑是否映射进现有 feed
- 参考：
  - https://www.mediawiki.org/wiki/API:Main_page
  - https://www.mediawiki.org/wiki/API:REST_API
